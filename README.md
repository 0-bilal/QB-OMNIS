# QB-OMNIS — لوحة التحكم بالمواقع

لوحة تتحكم في تشغيل وإطفاء مواقعك المنشورة على GitHub Pages، بتكلفة صفر.

**طريقة العمل:** عند الإطفاء، تحوّل اللوحة مصدر نشر GitHub Pages للموقع إلى فرع `maintenance` لا يحتوي إلا صفحة "الموقع مغلق حالياً". وعند التشغيل، ترجع المصدر الأصلي (فرع أو GitHub Actions) كما كان. هذا إغلاق حقيقي: ملفات الموقع لا تُرسل للزوار إطلاقاً.

## الملفات

| الملف | الوظيفة |
|---|---|
| `index.html`, `style.css`, `app.js` | لوحة التحكم |
| `firebase-config.js` | إعدادات Firebase ومعرّفك (تعدّله مرة واحدة) |
| `maintenance-template.js` | تصميم صفحة الإغلاق |
| `lock.js` | سكربت الإغلاق الفوري (اختياري) للمواقع الفرعية |
| `firestore.rules` | قواعد أمان قاعدة البيانات |

## خطوات الإعداد

### 1. إنشاء مشروع Firebase
1. افتح [console.firebase.google.com](https://console.firebase.google.com) وأنشئ مشروعاً جديداً (يمكن إيقاف Google Analytics).
2. من **Build ← Firestore Database** اضغط **Create database**، واختر موقعاً قريباً، وابدأ بـ **production mode**.
3. من **Build ← Authentication ← Get started**، فعّل مزوّد **Google**.
4. في **Authentication ← Settings ← Authorized domains** أضف: `0-bilal.github.io`
5. من **Project settings ← Your apps** اضغط أيقونة الويب `</>`، وسجّل تطبيقاً (بدون Firebase Hosting)، وانسخ قيم `firebaseConfig` إلى ملف `firebase-config.js`.

### 2. رفع اللوحة إلى GitHub
1. ارفع كل الملفات إلى مستودع `QB-OMNIS` (Add file ← Upload files).
2. في **Settings ← Pages** اختر **Deploy from a branch**، ثم `main` و `/ (root)`.
3. افتح `https://0-bilal.github.io/QB-OMNIS/`.

### 3. تحديد حسابك كمالك
1. سجّل الدخول في اللوحة بحساب Google. ستظهر رسالة "غير مصرّح" ومعها **معرّفك (UID)**.
2. ضع المعرّف في `ADMIN_UID` داخل `firebase-config.js` وارفعه من جديد.
3. ضع نفس المعرّف داخل الدالة `isAdmin()` في `firestore.rules` (المعرّف الحالي موضوع مسبقاً)، ثم انسخ محتوى الملف إلى **Firestore ← Rules** في Firebase واضغط **Publish**.

### 4. مفتاح GitHub
أنشئ مفتاحاً من [Fine-grained tokens](https://github.com/settings/personal-access-tokens/new):
- **Repository access:** All repositories (أو مواقعك فقط)
- **Permissions (Read and write):** Administration، Contents، Pages، Actions
- حدّد تاريخ انتهاء

الصقه في اللوحة. يُحفظ في متصفحك فقط، **ولا ترفعه إلى GitHub أبداً**.

## الاستخدام
- **ربط بالموقع:** ينشئ فرع `maintenance` ويسجّل الموقع في Firestore.
- **إغلاق الموقع:** تفتح نافذة تختار فيها **سبب الإغلاق**: انتهى اشتراك الخدمة، الخدمة غير متاحة حالياً، أعمال صيانة (مع موعد العودة المتوقع)، تحديث وتطوير، إيقاف إداري، أو سبب مخصص. كل سبب يملأ رسالة جاهزة وعنواناً مناسباً لصفحة الإغلاق، وتظهر معاينة مباشرة قبل التأكيد. يمكنك حفظ الرسالة كـ«رسالة جاهزة» لاستخدامها لاحقاً.
- **تعديل:** يغيّر سبب الإغلاق ونص الصفحة والموقع مغلق.
- **تحديث صفحات الإغلاق:** زر أعلى اللوحة (يظهر عند وجود مواقع مغلقة) يعيد نشر صفحة الإغلاق لكل المواقع المغلقة دفعة واحدة، بنفس الرسالة والسبب والتاريخ، لتحصل على آخر نسخة من القالب. commit واحد في فرع `maintenance` لكل موقع، ولا يتغير شيء آخر.
- **فتح الموقع:** نافذة تأكيد تعرض سبب الإغلاق ومدته والمصدر الذي سيعود إليه النشر. مواقع GitHub Actions يُعاد تشغيل آخر نشر ناجح لها تلقائياً.
- **التصنيفات:** اضغط على تصنيف البطاقة أو «خيارات أخرى ← تغيير التصنيف». أضف تصنيفات جديدة من القائمة الجانبية. تُحفظ في Firestore (`meta/config`).
- **اسم الخدمة:** من «خيارات أخرى ← تعديل اسم الخدمة». يظهر في البطاقة وصفحة الإغلاق.
- **الزيارات:** تظهر في بطاقة كل موقع مربوط: زيارات **التشغيل** و**الإغلاق** لليوم وآخر 7 أيام والإجمالي، مع رسم لآخر 14 يوماً، وإجمالي آخر 30 يوماً في أعلى اللوحة. التفاصيل في قسم «عدّاد الزيارات» أدناه.
- **سجل العمليات:** كل إغلاق وفتح وتحديث يُسجّل ويظهر أسفل اللوحة وفي صفحة «سجل العمليات».

> **بعد التحديث إلى الإصدار 5:** انشر قواعد `firestore.rules` الجديدة (انظر «عدّاد الزيارات» أدناه).
>
> **بعد التحديث إلى الإصدار 4:** انسخ محتوى `firestore.rules` الجديد إلى **Firestore ← Rules** واضغط **Publish**. بدون ذلك تعمل اللوحة، لكن لن تظهر الزيارات ولن تُحفظ التصنيفات والسجل.

## تحديث ملفات اللوحة
عند تعديل أي ملف من ملفات اللوحة، ارفع رقم الإصدار (مثلاً من `?v=7` إلى `?v=8`) في كل الأماكن التالية، حتى يحمّل المتصفح الملفات الجديدة فوراً بدل النسخة المحفوظة مؤقتاً:
- `index.html`: رابطا `style.css` و`app.js`
- `app.js`: استيراد `firebase-config.js` و`maintenance-template.js`، والثابت `APP_VERSION`
- `lock.js`: استيراد `firebase-config.js` و`maintenance-template.js`

رقم الإصدار يظهر أسفل اللوحة، فتعرف منه أي نسخة تعمل عندك.

> ملاحظة: GitHub يخزّن الصفحات مؤقتاً، فقد يرى بعض الزوار النسخة السابقة حتى 10 دقائق.

## الإغلاق الفوري (اختياري)
يُغلق الموقع **لحظة الضغط على الزر** عند كل الزوار، حتى من يتصفحه الآن، ثم يكتمل الإغلاق الحقيقي من GitHub Pages خلال دقيقة أو دقيقتين.

**التفعيل من اللوحة:** على بطاقة الموقع (مربوط ويعمل) اضغط **خيارات أخرى ← الإغلاق الفوري**. يفعّل ذلك أيضاً عدّاد الزيارات. تضيف اللوحة سطراً واحداً داخل `<head>` في commit جديد:
- **مواقع النشر من فرع:** في كل ملفات `.html` في مجلد النشر.
- **مواقع GitHub Actions (React/Vite):** في `index.html` الرئيسي، أو `public/index.html`.

> إذا كانت لديك نسخة من المشروع على جهازك، اسحب التحديث (`git pull`) قبل أن تعدّل عليها، حتى لا يحدث تعارض.

**يدوياً:** يمكنك إضافة السطر بنفسك داخل `<head>`:

```html
<script type="module" data-qb-omnis src="https://0-bilal.github.io/QB-OMNIS/lock.js?site=اسم-المستودع"></script>
```

**الإزالة:** من **خيارات أخرى ← الإغلاق الفوري** مرة أخرى، فيُحذف السطر من الملفات.

## عدّاد الزيارات
يعدّ الزيارات **الحقيقية** لكل موقع، مفصولة حسب حالة الموقع وقت الزيارة: **مفتوح** أو **مغلق**.

**كيف يعمل:**
- لكل موقع ولكل يوم مستند واحد في Firestore: `stats/{اسم-المستودع}/days/{YYYY-MM-DD}` (التاريخ بتوقيت UTC) فيه حقلان: `open` و`closed`.
- كل زيارة = كتابة واحدة فقط (زيادة الحقل بمقدار 1). الإجمالي = مجموع المستندات اليومية.
- **زيارة واحدة لكل جلسة تصفح:** تحديث الصفحة أو التنقل بين صفحات الموقع في نفس الجلسة لا يُحسب مرة أخرى (يُحفظ ذلك في `sessionStorage` بالمفتاح `qb-omnis:visit:{الموقع}:{الحالة}`). فتح الموقع في تبويب جديد يُعدّ جلسة جديدة.
- لا تُحسب زيارات المتصفحات الآلية (`navigator.webdriver`)، ولا تُحسب إلا للمواقع المربوطة باللوحة.
- العدّاد لا يمكن أن يعطّل الموقع: كل شيء داخل `try/catch`، وإن فشل يبقى الموقع كما هو.

**زيارات التشغيل (مفتوح):** يعدّها سكربت الإغلاق الفوري `lock.js`، لذلك **تحتاج تفعيل ⚡ الإغلاق الفوري** على الموقع. المواقع المفعّل عليها مسبقاً تبدأ العدّ تلقائياً بدون أي commit جديد في مستودعاتها.

**زيارات الإغلاق (مغلق):** صفحة الإغلاق نفسها تحتوي عدّاداً صغيراً، فتُعدّ زياراتها في **كل** المواقع المغلقة، حتى بدون الإغلاق الفوري. صفحات الإغلاق المنشورة سابقاً **لا تحتوي العدّاد** إلى أن تعيد نشرها: اضغط **تحديث صفحات الإغلاق** أعلى اللوحة لتحديثها كلها مرة واحدة، أو **تعديل** ثم احفظ على موقع واحد.

> لا تُحسب الزيارة المغلقة مرتين: إذا عرض `lock.js` صفحة الإغلاق فوراً ثم انتقل الزائر لصفحة الإغلاق الحقيقية، فالمفتاح نفسه في `sessionStorage` يمنع العدّ الثاني.

**الحصة المجانية (Spark):** 20,000 كتابة و50,000 قراءة يومياً. كل زيارة = كتابة واحدة + قراءة واحدة (تتحقق القواعد أن الموقع مسجّل). فتح اللوحة يقرأ تقريباً 17 مستنداً كحد أقصى لكل موقع مربوط (آخر 14 يوماً + 3 استعلامات تجميع). أي أن المواقع تتحمّل قرابة 20 ألف زيارة (جلسة) يومياً مجتمعة قبل أن يتوقف العدّ حتى اليوم التالي، والمواقع نفسها لا تتأثر.

**العدّاد القديم:** زيارات الإصدار 4 (`visits/{الموقع}`) تُضاف تلقائياً إلى زيارات التشغيل في اللوحة، فلا يضيع شيء.

**⚠️ خطوة مطلوبة:** بدون قواعد Firestore الجديدة لن تُحفظ الزيارات ولن تظهر. انسخ محتوى `firestore.rules` كاملاً إلى **Firebase Console ← Firestore Database ← Rules** واضغط **Publish**.
